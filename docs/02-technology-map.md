## Detailed Technology Breakdown & Interview Readiness

### 1. FastAPI (`backend/app/api/`)
- **Problem Solved**: High throughput, typed REST endpoints with automatic OpenAPI documentation.
- **Concepts Demonstrated**: Asynchronous path operations, dependency injection (`Depends`), global exception handling.
- **Interview Question**: *Why choose FastAPI over Flask or Django for an ML backend?*
  - *Answer*: FastAPI is built on Starlette and Pydantic, providing native async support (ASGI), automatic data validation, high performance comparable to Node.js/Go, and autogenerated OpenAPI docs out of the box.

### 2. Feature Store Abstraction (`backend/app/feature_store/`)
- **Problem Solved**: Ensures training-serving feature consistency and allows point-in-time historical retrieval.
- **Concepts Demonstrated**: Feature definitions, feature versions, materialization pipelines, lineage tracking.
- **Interview Question**: *What is training-serving skew and how does your feature store prevent it?*
  - *Answer*: Training-serving skew occurs when feature logic during inference differs from training logic. Our centralized feature engineering module (`backend/app/ml/feature_engineering.py`) is used by both the Feature Store materializer and inference service, ensuring 100% contract parity.

### 3. Ollama / Local LLM Insights (`backend/app/llm/`)
- **Problem Solved**: Generates executive retention summaries without leaking PII or sending sensitive HR data to external cloud LLM APIs.
- **Concepts Demonstrated**: Structured LLM context preparation, grounded generation, temperature control, fallback handling.
- **Interview Question**: *How do you prevent hallucinations when using an LLM for HR decision support?*
  - *Answer*: The LLM receives strictly pre-aggregated Statistical Summaries (from Pandas/NumPy), never raw records or individual employee names. The system prompt constrains the model to reference only provided statistics and explicitly forbids claiming causal connections without data.
